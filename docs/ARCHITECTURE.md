# 架构与代码约定

协议核心必须能脱离网络、设备和 GStreamer 测试。自有核心禁止 `unsafe`；平台 FFI 后续放在独立后端并单独审查。当前不添加未使用的网络/密码/媒体依赖。

| 边界 | 职责 |
|---|---|
| `airplay-core` | 有界 wire parsing、协议类型；后续加入纯状态与密码逻辑 |
| `airplay-cli` | 当前为离线诊断入口；后续负责配置、运行与日志 |
| 网络/会话（后续） | 会话拥有连接、任务、密钥与序号；统一取消和关闭 |
| 媒体 backend（后续） | 接收拥有明确 codec/format/PTS 的数据，隔离 GStreamer 线程与 ABI |
| 平台 backend（后续） | Bonjour AWDL、BlueZ、WinRT、BleuIO 和桌面服务 |

## Rust 约定

- Rust 2024 edition，标准 rustfmt。函数/变量 snake_case、类型 UpperCamelCase、常量 SCREAMING_SNAKE_CASE。
- 使用私有字段加必要的构造/访问方法保护不变量；枚举表达协议分支，不用魔法整数贯穿业务层。
- 外部输入不得触发 `unwrap`、`expect` 或断言；错误实现 `Display` / `Error`，包含足够诊断上下文，不打印密钥。
- wire 大小端显式转换，不依赖 CPU 对齐或内存布局。长度运算检查溢出，先验证再分配；限制可配置。
- 解析不顺带解密/渲染。未经认证的数据不能被标记为可信明文；NAL 解析仅接收已解密数据。
- 增量 decoder 明确定义 consumed、incomplete、EOF 和 fatal error 语义；错误后不猜测下一个帧的起点。
- 有状态协议使用单会话所有权和有界消息队列；避免用全局大锁封装整个原版。
- 公共接口写用途、约束与错误文档。注释解释协议原因或陷阱，不复述代码。
- 测试以 wire 行为和故障场景为依据，使用独立构造向量。测试可使用 `expect`，生产处理不依赖它。
- 不为未来功能堆空 crate 或抽象；真实边界出现时再拆分。

## 基线与兼容

保持正确的上游 wire 行为，不复现越界、未定义行为和日志笔误。未知类型保留以便更高层决策，格式错误返回错误。能力发布只能声明已经实现的功能；尚未接入服务发现时不广播“可用接收器”。

配置/CLI 对等需要记录 UxPlay 的单横杠多字符选项和原有优先级，不能默认改成 clap 常规选项后声称兼容。当前诊断 CLI 与未来兼容入口分开标注。
